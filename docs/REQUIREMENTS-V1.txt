大学生学习解锁娱乐软件 V1 详细需求文档
文档版本：V1.0
状态：需求冻结版
平台：Android 首发
使用范围：个人自用、本地单用户
说明：本文档作为 V1 开发与验收依据；后续新增功能进入 V2，不纳入本版。

1. 文档目的与范围
本文档定义 V1 的功能需求、页面流程、数据模型、权限约束、验收标准和开发优先级。
V1 目标：在 Android 上实现“学习达标后解锁娱乐应用，未达标强制拦截”，并配套虚拟积分奖惩、基础防作弊和本地备份。

2. 背景与目标
2.1 背景
大学生容易在抖音、游戏等娱乐应用上花费过多时间。需要一个工具，让用户先完成指定学习任务，才允许使用娱乐应用。

2.2 V1 目标
用户自行添加学习应用和娱乐应用。

自动检测学习应用前台使用时长。

用户手动录入学习内容完成度。

前台时长和完成度都达标后，当天解锁娱乐应用。

未达标时强制拦截娱乐应用。

通过虚拟积分进行奖励和惩罚。

基础防作弊，防止明显挂机和绕过。

数据本地保存，支持导出/导入备份。

3. 术语
术语	定义
学习应用	用户指定用于学习的应用，前台使用会计入学习时长
娱乐应用	用户指定需要限制的应用，如抖音、游戏
每日目标	每天 0 点生成的当日学习与解锁规则快照
达标	学习前台总时长 ≥ 目标时长，且完成度 = 100%
解锁	达标后，娱乐应用在当天 23:59 前允许使用
拦截	未达标时，打开娱乐应用被覆盖页阻止
奖励积分 R	完成目标后系统虚拟记账增加的积分
惩罚积分 F	未完成目标时直接扣除的积分
现实奖励核销	用户在现实兑现奖励后，手动扣除积分
紧急退出	临时暂停拦截 5 分钟，每日限次
4. 用户与使用场景
4.1 用户
单个大学生用户。

本地单用户，不做登录、不做账号体系。

数据仅保存在本机。

4.2 典型场景
首次使用，完成权限授权和初始配置。

每天打开学习应用，软件自动计时。

学习过程中手动更新完成度。

达标后娱乐应用当天解锁。

未达标打开娱乐应用，被拦截并提示剩余任务。

紧急情况下临时退出拦截 5 分钟。

每日结算奖励或惩罚积分。

现实奖励兑现后，手动扣除积分。

导出备份，防止数据丢失。

5. V1 范围
5.1 V1 做
Android 客户端。

本地单用户。

学习应用前台时长自动计时。

学习完成度手动录入。

达标判定与当天解锁。

未达标强制拦截。

实名、未成年人限制。

云端同步、多设备。

PC 端。

每个学习应用独立目标。

高精度内容识别。

root、模拟器、专业破解检测。

社交、排行榜、多人监督。

6. 总体流程
首次启动 → 权限引导 → 初始配置。

每日 0 点或首次打开生成当日目标快照。

用户打开学习应用 → 自动计时。

用户手动录入完成度。

系统判断：时长达标且完成度 100% → 发放奖励积分 R，解锁娱乐应用到当天 23:59。

未达标打开娱乐应用 → 强制拦截页。

当天结束仍未达标 → 次日补结算，扣除惩罚积分 F。

用户现实奖励兑现后 → 手动扣除积分。

所有积分变化写入流水。

7. 功能需求
FR-01 本地单用户与初始化
首次启动进入欢迎页和权限引导。

不要求登录，不联网。

本地保存配置、记录、积分和日志。

首次使用需完成：

授权“使用情况访问权限”；
授权“无障碍服务”；
授权“悬浮窗权限”；
可选：电池优化白名单、自启动权限；
设置学习目标模板；
设置娱乐应用；
设置奖励积分 R 和惩罚积分 F。
FR-02 权限引导与状态检测
展示每项权限的用途、拒绝后果、当前状态。

必须权限未开启时，首页显示醒目提醒。

权限关闭时：

记录防作弊事件；

暂停解锁判定；

引导重新开启；

不静默失效。

必须权限：使用情况访问、无障碍服务、悬浮窗。

可选权限：通知、电池优化白名单、自启动。

FR-03 学习应用配置
用户从已安装应用列表选择学习应用，支持搜索。

可添加多个学习应用。

V1 按多个学习应用的前台时长累计计算总学习时长。

用户设置每日学习总时长目标，单位分钟。

完成度目标固定为 100%，用户手动录入当前完成度百分比。

同一应用不能同时加入学习应用和娱乐应用。

系统必需白名单应用不可选为学习或娱乐应用。

配置修改次日生效；当日目标快照锁定。

FR-04 娱乐应用配置
用户从已安装应用列表选择娱乐应用，支持搜索。

可添加多个娱乐应用。

多个娱乐应用共用同一套学习目标。

未达标时，所有娱乐应用均强制拦截。

达标后，所有娱乐应用当天解锁到 23:59。

不能与学习应用重复。

配置修改次日生效；当日目标快照锁定。

FR-05 每日目标生成与快照
每天 0 点生成当日目标；若 0 点未运行，首次打开时补生成。

当日目标快照包含：

学习应用列表；

娱乐应用列表；

每日学习总时长目标；

完成度目标 100%；

奖励积分 R；

惩罚积分 F；

紧急退出每日次数；

随机验证参数。

当日目标生成后，上述规则锁定，修改模板次日生效。

每天只能有一个当日目标。

跨天学习按 0 点切分，分别计入对应日期。

FR-06 学习计时
只有学习应用处于前台且屏幕活跃时计时。

切出学习应用、锁屏、息屏时暂停计时。

多个学习应用前台时长累计。

计时误差要求：每小时不超过 10 秒。

分屏、画中画：记录异常事件，V1 不强制拦截，不额外计时。

学习时长自动统计，V1 不提供手动修改时长；纠错需“手动调整”并记录原因。

FR-07 完成度录入
用户在学习页手动录入完成度百分比，范围 0～100%。

可多次更新，取最新值。

允许当天补录，记录录入时间。

达标时锁定当日完成度。

次日不可修改前一日完成度。

完成度记录标记“手动录入”。

FR-08 达标判定与解锁
达标条件：

学习前台总时长 ≥ 当日目标时长；
完成度 = 100%。
两个条件同时满足时：

立即发放奖励积分 R；

娱乐应用解锁到当天 23:59；

记录解锁时间；

当日目标状态变为“已解锁”。

达标后当天解锁不可撤销。

达标后继续学习可继续记录，但不重复发放奖励。

奖励只发放一次，需防重复。

FR-09 娱乐拦截
未达标时，用户打开娱乐应用，无障碍服务识别前台包名后触发拦截。

拦截页全屏覆盖，显示：

今日学习总时长进度；

剩余学习时长；

当前完成度；

返回学习按钮；

今日娱乐已用时长；

紧急退出按钮及剩余次数。

拦截响应时间目标 ≤ 1 秒。

达标后当天不再拦截。

紧急白名单应用永不拦截。

V1 只处理前台全屏应用；分屏、画中画记录异常但不强拦。

FR-10 紧急白名单与紧急退出
内置系统必需白名单，不可移除：

电话、短信、系统设置、支付、地图、时钟、相机等。

V1 用户不可编辑白名单，避免绕过。

拦截页提供“紧急退出 5 分钟”：

全局暂停拦截 5 分钟；

每日最多 2 次；

使用后记录事件；

不延长当天解锁时间；

5 分钟后自动恢复拦截。

次数用尽后按钮不可用。

FR-11 随机验证与防作弊
学习期间随机弹出轻量验证，默认每 20～40 分钟一次。

验证形式：点击确认或简单算术。

验证失败：

暂停学习计时；

记录失败事件；

验证成功后恢复计时。

记录以下异常事件：

权限关闭；

系统时间跳变；

学习期间切出；

娱乐应用尝试打开；

验证失败；

紧急退出；

分屏/画中画。

时间篡改检测：检测系统时间明显跳变并记录，不直接阻止。

V1 防“偷懒”，不防专业破解。

FR-12 虚拟积分奖惩
积分余额上限 1000，不能为负。

创建目标模板时设置：

奖励积分 R；

惩罚积分 F；

校验 F ≤ 当前可用积分。

目标模板创建后锁定 R/F，修改次日生效。

完成目标：

系统虚拟记账直接增加 R；

若增加后超过 1000，封顶 1000，超出部分不发放并记录。

未完成目标：

次日补结算时直接扣除 F；

不冻结、不解冻；

若可用积分不足 F，扣至 0，并记录“惩罚未足额扣除”；

不产生负分。

不发放奖励时，不扣惩罚。

每个当日目标奖励和惩罚各最多执行一次。

FR-13 现实奖励核销与积分流水
积分页提供“扣除积分/现实奖励核销”按钮。

用户输入扣除积分和原因，默认原因“现实奖励核销”。

扣除不能超过当前可用积分，不能扣成负数。

每次变化写入流水，字段包括：

时间；

类型：目标完成奖励、惩罚扣除、现实奖励扣除、手动调整；

积分变化；

变化后余额；

原因；

关联当日目标。

手动调整仅用于纠错，必须填原因；增加不能超 1000，减少不能为负。

FR-14 记录与统计
提供今日和历史记录：

学习记录：日期、学习应用、开始/结束时间、时长；

娱乐使用记录：应用、开始/结束时间、时长；

积分流水；

异常事件日志。

首页展示今日学习进度、完成度、解锁状态、积分余额、剩余紧急退出次数。

V1 统计以今日和简单历史列表为主。

FR-15 备份与恢复
支持 JSON 导出，包含配置、每日目标、学习记录、娱乐记录、积分流水、异常日志。

支持 JSON 导入，导入前提示会覆盖本地数据。

导出文件由用户自行保存。

卸载或清除数据会丢失本地数据，需在设置页提示。

版本升级需做数据迁移。

FR-16 重启恢复与异常处理
手机重启后，拦截服务应尝试恢复。

权限可用时恢复拦截；权限不可用时通知并引导。

前台服务、无障碍服务异常断开时记录并提示。

应用崩溃后重新打开，数据不丢失，当日目标状态可恢复。

未结算的当日目标在下次启动时补结算。

8.2 主要流程
首次使用：欢迎 → 权限引导 → 学习目标 → 娱乐应用 → 积分规则 → 首页。

每日学习：打开学习应用 → 自动计时 → 手动更新完成度 → 达标 → 发放奖励并解锁。

未达标拦截：打开娱乐应用 → 拦截页 → 返回学习 / 紧急退出。

每日结算：完成时立即奖励；未完成次日补扣惩罚。

现实奖励：积分页 → 扣除积分 → 填原因 → 流水记录。

备份：设置页 → 导出/导入。

10. 非功能需求
性能：首页加载 ≤ 1 秒；拦截响应 ≤ 1 秒；计时误差 ≤ 10 秒/小时。

兼容性：建议最低 Android 8.0（API 26），目标 Android 14；具体最低版本实现前确认。

隐私：V1 不联网，数据仅本地；导出由用户主动操作。

稳定性：崩溃、重启后数据不丢；未结算目标可补结算。

电量：检测频率合理，避免频繁唤醒。

可维护性：模块化，便于 V2 增加云同步、真实支付、PC 端。

安全：本地数据做基本校验，防止误改；导出文件提示妥善保存。

11. 权限与技术约束
11.1 必需权限
使用情况访问权限：统计前台使用时长。

无障碍服务：监听前台应用切换，触发拦截。

悬浮窗权限：展示拦截覆盖页。

前台服务/通知：保证计时和拦截服务运行。

开机自启：重启后恢复服务。

11.2 可选权限
电池优化白名单；

自启动权限；

通知权限。

11.3 技术约束
无障碍服务和悬浮窗无法保证 100% 不可绕过。

UsageStatsManager 在 Android 14+ 可能无法返回最新实时数据，需用无障碍事件交叉校验。

厂商 ROM 可能杀后台，需引导电池优化和自启动。

个人自用场景接受“防偷懒，不防专业破解”。

强制拦截不是系统级不可绕过。

14. 风险与假设
14.1 风险
厂商 ROM 杀后台导致拦截失效。

无障碍服务被系统关闭。

Android 14+ 使用统计延迟。

完成度手动录入可作弊，需日志留痕。

本地数据可能因卸载或清数据丢失。

强制拦截无法做到绝对不可绕过。

14.2 V1 假设
最低 Android 版本实现前确认，建议 Android 8.0+。

多个学习应用按总时长累计。

每日 0 点重置，达标解锁到 23:59。

目标模板修改次日生效。

紧急退出全局暂停 5 分钟，每日 2 次。

随机验证每 20～40 分钟一次。

内置白名单不可编辑。

奖励积分虚拟记账直接加，上限 1000。

惩罚直接扣分，不冻结解冻。

未完成且积分不足时扣至 0 并记录。
