# 需求补充与待确认项

## 已确认

- Android 首发，个人自用，本地单用户。
- 初始积分在首次使用时由用户填写。
- 开发项目当前最低系统为 Android 15 / API 35，替代原文 Android 8.0 的建议值。
- 积分不涉及真实支付、冻结或资金托管。

## 建议，尚待用户确认

- 初始积分采用 0～1000 的整数；初始化后纠错通过有原因的手动调整。
- 解决原文“未完成扣惩罚”与“不发放奖励时不扣惩罚”的矛盾：建议完成只奖励，未完成只惩罚，同一目标不同时发生。
- 首日是否仅体验、次日开始正式考核。
- 连续多天未启动时，是否逐日生成目标并扣分。
- 随机验证等待超时长度，以及等待期间的计时方式。
- 学习时长纠错入口、审计记录与权限关闭后的缺失时间处理。
- 日期与时区策略，午夜截止采用下一日 00:00 的半开区间。
- 导入旧备份导致积分和紧急退出次数回退的处理。
- 白名单的必要系统包识别方式，不将未知包默认视为安全应用。
- 备份是否加密、文件位置与导入校验策略。

原始需求的“配置冻结”不代表实现歧义已解决。编码前逐项明确上述规则，并记录变更。
